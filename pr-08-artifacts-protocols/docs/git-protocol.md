# Протокол работы с Git

Команда использует упрощённую модель GitHub Flow: ветка `main` всегда рабочая, новая работа ведётся в отдельных ветках. Непосредственные коммиты в `main` запрещены (защищённая ветка).

## Именование веток

| Ветка | Правило имени | Пример |
|---|---|---|
| `main` | Основная, стабильная, защищена от прямой записи | `main` |
| `feature/*` | `feature/<модуль>-<суть>`, новая функция или модуль | `feature/rfid-scan-parser` |
| `bugfix/*` | `bugfix/<номер задачи>-<суть>`, исправление ошибки | `bugfix/142-qr-empty-code` |

## Сообщения коммитов

Схема «тип: суть», типы: `feat`, `fix`, `docs`, `test`. Пример: `feat: разбор RFID-метки`.

## Условия слияния нового модуля

Pull request из feature-ветки в `main` принимается, только если:

1. все автотесты и сборка в CI прошли успешно;
2. есть минимум одно одобрение (approve) от ревьюера, который не является автором;
3. ветка актуальна относительно `main` и не имеет конфликтов;
4. к изменению приложены тесты и обновлён `openapi.yaml`, если менялся API.
